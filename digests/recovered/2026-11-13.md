# Weekly LLM Papers Digest — 2026-11-13

> **Source note:** arXiv (`arxiv.org`, `export.arxiv.org`) was unreachable from this run's network policy, so **no abstracts were read this run**. Summaries below come from general prior knowledge of these well-known papers; specific numbers are deliberately kept to a minimum and should be checked against the linked papers.

## TL;DR

- **Model Architecture and Efficiency** — *DeepSeek-V3 Technical Report*: a large sparse MoE model with Multi-head Latent Attention, showing frontier-class open models can be trained at unusually low cost.
- **Preference Optimization and RLHF** — *SimPO: Simple Preference Optimization with a Reference-Free Reward*: drops DPO's reference model and uses a length-normalized reward with a target margin, making it simpler and cheaper to run.
- **Multimodal Models** — *Chameleon: Mixed-Modal Early-Fusion Foundation Models*: one token-based transformer that reads and writes interleaved images and text from the start of training.
- **Long-Context Learning and Inference** — *LongRoPE: Extending LLM Context Window Beyond 2 Million Tokens*: searches non-uniform RoPE rescaling factors so context can be extended to 2M+ tokens with limited fine-tuning.
- **Reasoning and Knowledge** — *DeepSeek-R1: Incentivizing Reasoning Capability in LLMs via Reinforcement Learning*: large-scale RL with rule-based rewards brings out long chain-of-thought reasoning, released with open weights.
- **Quantization and Compression** — *The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits*: BitNet b1.58 trains ternary-weight ({-1, 0, 1}) LLMs from scratch that it claims match FP16 baselines at scale.
- **Evaluation and Benchmarks** — *A Careful Examination of Large Language Model Performance on Grade School Arithmetic*: builds GSM1k, a fresh GSM8K-style set, to measure contamination and overfitting.
- **Instruction Tuning and Alignment** — *TÜLU 3: Pushing Frontiers in Open Language Model Post-Training*: a fully open post-training recipe (SFT → DPO → RL with verifiable rewards), released with data, code and evals.
- **Surveys and Meta-Analysis** — *The Prompt Report: A Systematic Survey of Prompting Techniques*: a systematic taxonomy and vocabulary for prompting techniques.
- **Applications and Tooling** — *AlphaEvolve: A Coding Agent for Scientific and Algorithmic Discovery*: an LLM-driven evolutionary coding agent that finds better algorithms when given automated evaluators.

## Details

### Model Architecture and Efficiency — DeepSeek-V3 Technical Report
S.No. 531 · [arXiv:2412.19437](https://arxiv.org/abs/2412.19437)

DeepSeek-V3 is a large Mixture-of-Experts language model with only a small fraction of its parameters active per token. It builds on DeepSeek-V2's Multi-head Latent Attention (MLA, which compresses the KV cache) and the DeepSeekMoE design. The report also covers an auxiliary-loss-free load-balancing strategy, a multi-token prediction training objective, FP8 mixed-precision training, and heavy co-design of the training framework and communication. **Why it matters:** it became a reference point for how much frontier-level capability can be had per unit of training compute, and it is the base model behind DeepSeek-R1. **Caveats:** the headline training-cost figure covers only the final training run, not research, ablations or data costs. Abstract not read this run.

### Preference Optimization and RLHF — SimPO: Simple Preference Optimization with a Reference-Free Reward
S.No. 109 · [arXiv:2405.14734](https://arxiv.org/abs/2405.14734)

SimPO changes DPO by using the policy's own length-normalized average log-likelihood as the implicit reward. That removes the frozen reference model, and a target reward margin is added to the Bradley–Terry objective. **Why it matters:** it saves the memory and compute of the reference model and directly targets length exploitation. The paper reports strong results on chat benchmarks such as AlpacaEval 2 and Arena-Hard. **Caveats:** later work found it sensitive to hyperparameters (the margin and β), and without a reference-model anchor it can drift further from the base model. Gains depend on the benchmark. Abstract not read this run.

### Multimodal Models — Chameleon: Mixed-Modal Early-Fusion Foundation Models
S.No. 123 · [arXiv:2405.09818](https://arxiv.org/abs/2405.09818)

Chameleon (Meta) turns images into discrete tokens and trains one transformer on interleaved image and text token sequences from scratch ("early fusion"). The same model can understand and generate any mix of text and images. The paper spends a lot of space on the optimization-stability fixes needed to train such a model, such as QK-norm and changes to norm placement. **Why it matters:** it is a clear demonstration of the unified token-based alternative to bolting a vision encoder onto an LLM, and it shaped later "omni" model designs. **Caveats:** image tokenization limits generation quality, and the public release restricted image generation. Abstract not read this run.

### Long-Context Learning and Inference — LongRoPE: Extending LLM Context Window Beyond 2 Million Tokens
S.No. 56 · [arXiv:2402.13753](https://arxiv.org/abs/2402.13753)

LongRoPE (Microsoft) extends a pretrained model's context window by searching for non-uniform rescaling factors per RoPE dimension and position, rather than interpolating positions uniformly. It also uses a progressive extension strategy (extend a moderate amount, fine-tune, then extend again) and readjusts the factors to keep short-context performance. **Why it matters:** it pushed RoPE-based context extension to the 2M-token scale with relatively little long-sequence fine-tuning, and similar ideas later appeared in production models (e.g., Phi-3 long-context variants). **Caveats:** a model that *accepts* very long inputs does not necessarily *use* them well. Retrieval and reasoning quality at extreme lengths should be checked on harder benchmarks than perplexity or passkey retrieval. Abstract not read this run.

### Reasoning and Knowledge — DeepSeek-R1: Incentivizing Reasoning Capability in LLMs via Reinforcement Learning
S.No. 532 · [arXiv:2501.12948](https://arxiv.org/abs/2501.12948)

DeepSeek-R1-Zero applies large-scale RL (GRPO with rule-based accuracy and format rewards) directly to a base model. Long chain-of-thought behaviours such as self-verification and reflection emerge without supervised reasoning data. DeepSeek-R1 adds a small cold-start SFT stage and multi-stage RL to fix readability and language mixing. The team also distilled R1's reasoning traces into smaller dense models. **Why it matters:** it was the first open-weights model reported to be competitive with OpenAI's o1 on reasoning benchmarks, and it set off the wave of "R1-style" RLVR work that fills much of this list. **Caveats:** later papers (several in this list) argue that much of the gain may sharpen abilities the base model already had rather than create new ones. R1-Zero's outputs are hard to read. Abstract not read this run.

### Quantization and Compression — The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits
S.No. 65 · [arXiv:2402.17764](https://arxiv.org/abs/2402.17764)

BitNet b1.58 trains LLMs from scratch with ternary weights {-1, 0, +1} (≈1.58 bits) and low-bit activations. The paper claims that from a few billion parameters upward it matches full-precision LLaMA-style baselines on perplexity and downstream tasks, while greatly cutting memory, latency and energy. **Why it matters:** this is quantization-aware *pretraining* rather than post-hoc quantization, and it argues for new hardware and kernels built around addition-heavy, multiplication-free arithmetic. **Caveats:** the original results came from fairly small models and token budgets. Real speedups need custom kernels or hardware. The approach does not compress existing pretrained models. Abstract not read this run.

### Evaluation and Benchmarks — A Careful Examination of Large Language Model Performance on Grade School Arithmetic
S.No. 116 · [arXiv:2405.00332](https://arxiv.org/abs/2405.00332)

The authors (Scale AI) wrote GSM1k, a new set of grade-school math problems matched to GSM8K in style and difficulty, and compared many models on both. Some model families dropped noticeably on GSM1k, which suggests overfitting or contamination. Frontier models showed little drop. The paper also links the size of the gap to how likely a model is to generate GSM8K examples verbatim. **Why it matters:** a clean, reusable method for checking whether benchmark scores reflect real capability. **Caveats:** GSM1k was kept private to avoid contamination, which limits independent reproduction. Some of the measured gap may come from small differences in distribution rather than contamination. Abstract not read this run.

### Instruction Tuning and Alignment — TÜLU 3: Pushing Frontiers in Open Language Model Post-Training
S.No. 515 · [arXiv:2411.15124](https://arxiv.org/abs/2411.15124)

TÜLU 3 (AI2) is a fully open post-training recipe applied to Llama 3.1 base models. It consists of curated and synthetic SFT data aimed at specific skills, then on-policy DPO, then *Reinforcement Learning with Verifiable Rewards* (RLVR) on tasks with checkable answers. Data, code, decontamination tooling and an evaluation suite are all released. **Why it matters:** it is one of the most transparent end-to-end post-training recipes, and it helped popularize the "RLVR" framing just before DeepSeek-R1. **Caveats:** results are tied to the Llama 3.1 base models and the chosen eval suite. Abstract not read this run.

### Surveys and Meta-Analysis — The Prompt Report: A Systematic Survey of Prompting Techniques
S.No. 126 · [arXiv:2406.06608](https://arxiv.org/abs/2406.06608)

A large, systematic (PRISMA-style) review of the prompting literature. It proposes a shared vocabulary and taxonomy covering text prompting techniques, multilingual and multimodal prompting, agents, evaluation, and safety/security issues, plus some small case studies. **Why it matters:** a good single reference for anyone who needs consistent terms for prompting methods. **Caveats:** prompting changes quickly, and reasoning models trained with RL make some techniques less relevant. Treat it as a map, not a ranking. Abstract not read this run.

### Applications and Tooling — AlphaEvolve: A Coding Agent for Scientific and Algorithmic Discovery
S.No. 568 · [arXiv:2506.13131](https://arxiv.org/abs/2506.13131)

AlphaEvolve (Google DeepMind) runs an evolutionary loop in which Gemini models propose code changes to whole programs and automated evaluators score them. The best candidates are fed back into later prompts. It has been applied to open math problems (including faster algorithms for small matrix multiplications) and to Google infrastructure tasks such as scheduling and kernel tuning. **Why it matters:** a concrete example of LLMs producing verifiable new results, not just helping humans write code. **Caveats:** it only works where a fast, reliable automated evaluator exists, and it uses a lot of compute. Abstract not read this run.
